# הזמר במסכה — גרסה עצמאית לפריסה

זוהי גרסה עצמאית, שאינה תלויה בפלטפורמת Claude, של אפליקציית התחרות
"הזמר במסכה". הלוגיקה כאן זהה 1:1 לאב-הטיפוס שנבנה ונבדק ב-Claude
(כולל חישוב סדר החשיפה לפי אחוז זיהוי, וטיברייק לפי מהירות תשובה) —
השינוי היחיד הוא שהיא מתחברת ל-Firestore אמיתי במקום למסד הנתונים
הפנימי של Claude, ולכן **אין כאן שום דרישת התחברות לקהל**: הזיהוי
היחיד של כל משתתף/ת הוא השם שהוא/היא מקליד/ה בכניסה.

## מבנה הקבצים

```
index.html        עמוד הקהל — הקישור שמשתפים עם כל המשתתפים (QR/קישור)
admin.html        עמוד הניהול — מוגן ב-PIN בלבד, נשאר אצל המפיק/ה
styles.css        כל העיצוב (זהה לחלוטין לאב-הטיפוס)
config.js         *הקובץ שעורכים לפני האירוע* — שמות, תמונות, PIN, Firebase
db-adapter.js      מתאם טכני בין הקוד ל-Firestore (אין צורך לגעת בו)
app.js             כל הלוגיקה של האפליקציה (אין צורך לגעת בו)
firestore.rules    כללי האבטחה של מסד הנתונים
firebase.json      קובץ תצורה נוח אם משתמשים ב-Firebase Hosting
photos/            תיקייה ריקה — לשים בה תמונות אמיתיות של המועמדים (רשות)
```

## שלב 1: מה בהכרח צריך לערוך — config.js

כל מה שכדאי לשנות נמצא בקובץ אחד: **config.js**. בתוכו, בעברית:

- **שמות ותמונות של המועמדים/ות**: מערך `CANDIDATES`. לכל מועמד/ת יש
  שדה `photo` — אם ממלאים אותו (למשל `"photos/12.jpg"` אחרי ששמים
  קובץ בתיקיית `photos/`, או כתובת אינטרנט מלאה לתמונה), התמונה
  האמיתית תוצג לקהל **במקום** האווטאר המצויר. משאירים `""` כדי
  להישאר עם האווטאר המצויר.
- **שמות/צבעים של 6 "השירים"**: מערך `SONGS`.
- **קוד הכניסה למסך הניהול**: `ADMIN_PIN` — חשוב לשנות מ-"2026"
  לקוד שלכם.
- **פרטי חיבור ל-Firebase**: `FIREBASE_CONFIG` — איך משיגים אותם
  מוסבר בשלב 2 למטה.

## שלב 2: הקמת פרויקט Firebase (חינמי, כ-5 דקות)

1. גולשים אל [console.firebase.google.com](https://console.firebase.google.com)
   ומתחברים עם חשבון Google.
2. **Add project** → נותנים שם (למשל `masked-singer-palram`) →
   ממשיכים עם ברירות המחדל (אפשר לכבות Google Analytics, לא נדרש) →
   Create project.
3. בתפריט הצד: **Build → Firestore Database** → **Create database**.
   בוחרים מיקום (למשל `eur3 (europe-west)`) ומצב **Production mode** →
   Enable. (על שכבת החינם — Spark — נפח השימוש של אירוע כזה זניח
   ולא אמור לעלות כסף.)
4. בתפריט הצד: **Build → Firestore Database → Rules** — מדביקים
   לשם את התוכן של הקובץ `firestore.rules` מהתיקייה הזו, ולוחצים
   **Publish**.
5. בעמוד הראשי של הפרויקט (סמל הבית) → לוחצים על סמל ה-Web `</>`
   כדי להוסיף אפליקציית Web → נותנים שם (למשל `masked-singer-web`)
   → **אין** צורך לסמן Firebase Hosting בשלב הזה → Register app.
6. מופיע קטע קוד עם אובייקט JavaScript שנקרא `firebaseConfig` —
   הוא נראה כך:
   ```js
   const firebaseConfig = {
     apiKey: "AIza...",
     authDomain: "masked-singer-palram.firebaseapp.com",
     projectId: "masked-singer-palram",
     storageBucket: "masked-singer-palram.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abcdef123456"
   };
   ```
   מעתיקים את שש השורות האלה (בלי ה-`const firebaseConfig =` ובלי
   הנקודה-פסיק) לתוך `FIREBASE_CONFIG` בקובץ `config.js`.

זהו — אין צורך ביצירת משתמשים, סיסמאות, או כל הרשמה נוספת. זה בדיוק
מה שמאפשר לקהל להיכנס בלי שום התחברות.

## שלב 3: פריסה (hosting)

הקבצים הם אתר סטטי לחלוטין (HTML/CSS/JS רגילים) — אפשר לארח אותם
בכל שירות אחסון אתרים סטטי. שתי אפשרויות נוחות:

### אפשרות א׳ — Firebase Hosting (מומלץ, מתחבר ישירות לאותו פרויקט)

דורש התקנת [Node.js](https://nodejs.org) פעם אחת במחשב, ואז בטרמינל,
בתוך התיקייה הזו:

```bash
npm install -g firebase-tools
firebase login
firebase use --add        # בוחרים את הפרויקט שיצרתם בשלב 2
firebase deploy
```

בסיום תקבלו כתובת קבועה בסגנון `https://masked-singer-palram.web.app`.
עמוד הקהל יהיה בכתובת הזו (`/index.html`), ועמוד הניהול ב-
`https://masked-singer-palram.web.app/admin.html`.

### אפשרות ב׳ — כל שירות אחסון סטטי אחר

מעלים את כל תוכן התיקייה הזו (חוץ מ-`firebase.json` ו-`firestore.rules`,
שאינם נחוצים לשירותים אחרים) לשירות כמו Netlify, Vercel, GitHub Pages,
או אפילו שרת קבצים סטטי פנימי של החברה. אין תלות ב-Firebase Hosting
עצמו — Firebase Hosting היה נוח כי הוא מתחבר ישירות לאותו פרויקט,
אבל **מסד הנתונים (Firestore) עובד זהה מכל מקום**, כי הוא מזוהה על
פי `FIREBASE_CONFIG` בקוד עצמו ולא לפי מיקום האחסון.

## שלב 4: שני הקישורים לאירוע

- **קישור הקהל** (`index.html`) — משתפים בכל ערוץ נוח: מסך QR
  בכניסה, הודעת וואטסאפ/מייל, וכו׳.
- **קישור הניהול** (`admin.html`) — נשאר אצל המפיק/ה בלבד. מוגן
  ב-PIN שהגדרתם, אבל מומלץ בכל זאת לא לשתף אותו באותו ערוץ — מי
  שמגיע לעמוד הזה ומזין את הקוד הנכון יכול לשלוט בכל מהלך הערב.

## שלב 5: בדיקה לפני האירוע

בדיוק כפי שנבדק באב-הטיפוס ב-Claude, כדאי לעבור על כל הרצף פעם אחת
לפני הערב:

1. נכנסים ל-`index.html` משני דפדפנים/מכשירים שונים ומקלידים שני
   שמות שונים.
2. נכנסים ל-`admin.html`, מזינים את ה-PIN, ופותחים הצבעה לביצוע 1.
3. מצביעים משני ה"משתתפים" על מועמדים שונים, וסוגרים את ההצבעה.
4. חוזרים על כך לביצועים 2–6 (או קופצים ישר לשלב "רצף חשיפות" לבדיקה
   מהירה יותר).
5. בעמוד הניהול לוחצים על "רשימת משתתפים" בסרגל הצד ומוודאים ששני
   השמות מופיעים.
6. עוברים לשלב "רצף חשיפות": בשלב 1 בוחרים בעמוד הניהול מי מסתתר
   מתחת לכל מסכה, ולוחצים "חשב/י סדר חשיפה" — מוודאים שהסדר שמתקבל
   בשלב 2 יורד מאחוז הזיהוי הגבוה ביותר לנמוך ביותר. לוחצים "חשוף
   את הבא" ומוודאים שכל משתתף רואה מיידית אם ניחש נכון.
7. עוברים לשלב "לוחות תוצאות" ומוודאים שהדירוג בטאב "מנחשים מובילים"
   נראה הגיוני (מי שניחש הכי הרבה נכון למעלה; במקרה תיקו, מי שהצביע
   מהר יותר על התשובות הנכונות מדורג ראשון).

## אם רוצים לאפס את הנתונים אחרי בדיקה ולפני האירוע האמיתי

בעמוד הניהול יש כפתור אדום "איפוס האירוע (למצב בדיקה)" בתחתית הסרגל
הצדדי — הוא מוחק את כל המשתתפים, ההצבעות, ומחזיר את מצב האירוע
לביצוע 1. הפעולה בלתי הפיכה, אז משתמשים בה רק כדי לנקות נתוני בדיקה
לפני הערב האמיתי (לא באמצע האירוע עצמו).

## שאלות נפוצות

**האם צריך לשלם על Firebase?**
עבור אירוע בודד עם כמה מאות משתתפים, הנפח רחוק מאוד ממכסת החינם
(Spark) של Firestore/Hosting. לא אמור להיות חיוב.

**מה קורה אם מישהו סוגר את הדפדפן באמצע האירוע?**
השם שלו נשמר מקומית במכשיר (`localStorage`), כך שאם הוא חוזר לאותו
קישור באותו מכשיר/דפדפן הוא ממשיך בדיוק מאיפה שעצר — בדיוק כמו
בגרסת האב-טיפוס.

**רוצה להחליף שם/תמונה של מועמד/ת ברגע האחרון, בעודי באירוע?**
עורכים את `config.js`, ואם משתמשים ב-Firebase Hosting מריצים שוב
`firebase deploy` (לוקח כמה שניות); בשירות אחסון אחר — מעלים מחדש
את הקובץ `config.js` המעודכן.
